# 工作流

## 总入口与子技能协作（0.8.0）

由[foodsci-start](../SKILL.md)识别本次目标，调用或读取实际相关子技能，不启动固定全流程。公开版六入口将相关任务分组，下面内部细分模块仍可按需读取。综述使用 literature→[literature-review](literature-review.md)→[polishing](polishing.md)；从论文到课题使用 literature→[research-planning](research-planning.md)→experimental-design；有数据并要成稿时使用[数据分析](data-analysis.md)→writing→polishing。现成文字的翻译润色直接进入 polishing；审稿和投稿仅按任务衔接。

生物、食品及交叉主题的稿件均适用领域术语、测量/解释边界及用户去防御表达检查。先交可用成稿，必要事实问题另列；无数据、全文或实际检索时完成有依据的部分，不补造结果、文献或系统综述计数。用户只要提纲或局部编辑时遵守该范围。具体分工见[子技能说明](subskills.md)。

## 研究问题、论文实验到数据与稿件

按任务从任何阶段进入，不要求完整管线：

1. 文献入口记录实际检索/读取范围，按[研究拆解](research-decomposition.md)建立主张—实验/组件—对照—结果与支持范围；相反证据及未测连接留痕。
2. 由替代解释选择最小判别试验，再用[食品方法目录](methods.md)与[交叉桥接](crossdisciplinary-bridges.md)核对体系、测量和迁移条件。样本量/参数未知先规划依据，不列固定全套检测。
3. 有数据时依[可复现分析](analysis-workflow.md)做数据字典、单位/样品层级和QC，再确定比较、效应、不确定性及实际可用方法。宿主具备执行条件时保存本任务代码、分析表、结果和输入/软件记录；否则交付未执行的计划，不假称已有数值。
4. 依[证据图表](figure-evidence.md)确定每图问题与数据来源。图注、中文英文结果和讨论共用事实记录，区分测量、计算、解释和应用；不能为叙事补实验。
5. 需要审稿或复审时核查同一证据链和修订影响，保留原ID；用户仅要设计/分析/写作时不强制先做外审。每阶段交接主张/样本ID、来源/版本、实际产物及未核验项。

这些是科研工作方式，不是本地批量执行器自动完成的LLM任务。来源机制及舍弃规则见[能力来源](research-capabilities.md)。

## A. 文献到证据表

触发：“筛选关于食品蛋白消化产物与巨噬细胞炎症指标的文献，优先原始研究。”

1. literature 确认范围、日期、物种/细胞与纳排标准，记录实际查询式、检索来源和日期。
2. 有搜索工具时获取真实记录；无网络时只筛用户提供的记录，标记覆盖范围。去重、筛选与排除理由逐条留痕；全文未取回就不能按全文结论填表。
3. DOI 工具核对题名与年份；有需要且用户允许 DOI 联网查询时显式使用 `--online`。元数据匹配不能证明试验数据、文章现状或论断支持性；仍须读原文对应段落/图表。
4. 交付筛选表、证据表与未核验清单。写作技能只使用可定位的证据。

## B. 实验设计与分析到结果初稿

触发：“帮我设计食品样品的抗氧化实验”或“对我上传的原始数据做质控，生成结果初稿”。

1. start 将采集前设计交给 experimental-design，已有数据交给 data-analysis；从 [方法目录](methods.md) 选择材料/体外、打印、发酵、斑马鱼/小鼠、功能、保鲜贮藏、生产或已登记的自定义方法，只加载相关模块。
2. 设计阶段先定义问题、因素与水平、对照、独立实验单位、技术重复、批次/随机化、主要终点和分析计划。缺少样本量依据时说明所需信息，不默认写“三重复足够”。已有数据时检查输入、单位、独立性与方法适用性；不满足条件则列出待补资料，保留可继续的质控工作。
3. 使用随包固定工具时核对实际支持范围，保留输入哈希与来源映射；下述批量执行器的数值计算仅支持模拟消化与RAW264.7。其他数据按上文可复现分析流程，在实际环境中另写/执行本任务代码或交付待运行方案，不把方法描述冒充运行结果。原始Excel/仪器表确认列映射后转换，不默改原件。批量执行器遇错误会停止并报告未运行任务。
4. writing 根据可追溯结果起草，按实际实施的方法描述；固定脚本输出仍为描述性汇总，不补 P 值、样本量或机制，再由polishing做领域与语言检查。
5. submission-review 核对结果与稿件，返回可定位的问题及修改建议。

新增实验类型见 [扩展入口](ADD_METHOD.md)。添加方法文档与目录行即可让技能按任务选择；新增自动计算能力仍需单独实现并验证脚本。

### 实际可运行的批量分析

在解压后的Skill根目录运行（路径由你自己的解压位置决定）：

```powershell
python -B scripts/run_workflow.py --config assets/examples/workflow.json --output-dir demo-results
```

结果目录必须尚不存在。执行器依次运行 RAW、消化和 DOI 状态三个任务；不启动网络请求、不执行 JSON 中的任意命令。合成 DOI 非法是预期的逐记录核验结果，并不等于任务执行失败。运行报告的 `needs_review` 为 true，DOI 任务为 `needs_review`，表明需要处理核验问题。核验状态仍必须阅读，不能将进程退出 0 当作文献已验证。

复制 `assets/examples/workflow.json` 创建自己的配置。`input` 相对配置文件所在目录，也可用用户明确提供的绝对路径；RAW 任务必须写 `reference_group`。不同参考组或不同归一化目的分为独立任务。批量输出仅为数值与核验状态；文献搜索、证据推理、写作和审查仍由宿主会话中的 Skill 执行，不在本地脚本中伪装成已完成。

任务 `id` 须唯一且为小写 kebab-case；`run-report` 保留给运行报告，不能用作任务名。配置检查在创建结果目录前完成，避免分析结果被运行报告覆盖。

## C. 中英文稿件到投稿审查

触发：“把这份中文稿转换成英文初稿，并按我的目标期刊审查。”

1. writing 以输入稿、确认的结果表和证据表建立事实清单，保留数字、方向、统计限定和引用身份。
2. 翻译或改写；提供关键改动说明与未决问题，研究未提供的部分显式待补。
3. submission-review 读取目标期刊当前官方指南并记日期；没能读取时标注“期刊要求未核验”，不能声称符合。
4. 交付可修改稿件、论断-证据映射和投稿前问题清单。提交系统操作、邮件或公开发布需用户另行明确指示。

## 如需日后定时运行

插件未注册定时任务。定时器不是 plugin.json 的臆造字段。用户选定主题、周期、时间/时区和通知渠道后，可由当时宿主支持的任务功能建立；能力与权限以实际会话为准。建议仅在出现新文献、流程完成、失败或需要用户补资料时通知。

可复用提示：“按已确认的检索范围与纳排标准检查新增文献，保留真实查询日志；只报告新增且符合标准的条目及其核验状态。没有变化时保持安静。无网络或权限时说明任务无法完成，不生成替代文献。”

## 食品领域专业审稿与复审

从食品领域审稿人的角度查核心论点时，先调用专业审稿路线，按实际稿件选择食品领域检查，形成论点/证据定位、Major/Minor及关闭标准，再按需要处理期刊要求或作者回复。修订复审先核对原问题与修稿，再核对作者回复，保留原ID；承诺修改不当作已经完成。无真正隔离调用时只报告单代理多角度审查，不编造多位专家共识。

0.4.0的设计与审稿共用打印、发酵、动物功能、保鲜及生产方法：先固定主张和独立单位，再检查证据，最后按真实修改起草改句/回复。跨阶段保留墨水/食品批次、打印或发酵运行、动物/缸笼、包装和生产批号的对应关系，不因跨模块、多个时间点或检测视野而增加独立n；只有确实实施的修复才写成已完成。
