# 数据契约与计算范围

以下是随包raw/digestion固定工具的CSV要求：UTF-8（允许BOM），首行为列名，一行一个原始观测；数值须有限且不能缺失。保留原始文件，另外做可追溯的格式转换。固定脚本不猜单位、不插补、不删异常值。附加列可保留，但不会参与分组；剂量、时间等不同条件必须使用不同的group/sample_id/stage，不能只放在被忽略的附加列。通用分析中的缺失或重复处理另按实际设计、QC与分析流程记录，不由此要求丢弃整份数据。

自 0.2.0 起，模拟消化与 RAW264.7 合并在“实验设计”Skill 下，原有 CSV 和脚本命令保持兼容。新增抗氧化、多糖、蛋白及自定义方法按各方法文档设计和分析，不能因为在目录中登记就套用本文件的 raw/digestion 数值处理。

CSV 引号必须正确闭合；含逗号或换行的字段使用标准 CSV 引用。未闭合等解析错误会拒绝整个输入，不生成分析结果；正确引用的多行字段可正常读取。

本文件定义随包固定分析程序的输入，不是所有食品数据的通用格式。0.5.0增加[通用分析工作方式](analysis-workflow.md)：宿主具备实际数据、执行环境和适用方法时，可另外编写/运行本任务代码并交付复现记录；这不扩展下述raw/digestion模式，也不代表已附带通用统计库。没有这些条件时交付计划或待运行代码，如实注明未执行。

## RAW264.7

必需列：`experiment_id,plate_id,well,group,endpoint,value,blank,unit`。

| 列 | 语义 |
| --- | --- |
| experiment_id | 用户确认的独立实验单位 ID；日期、孔位或重复读板不会自动构成独立单位 |
| plate_id / well | 实验内板与孔位；同实验/板/孔/终点不能重复 |
| group | 包含处理、浓度、时间和必要条件的唯一组标签 |
| endpoint | 单个测量指标；同名终点只允许一种单位 |
| value / blank | 原始值与适配该孔/样品/基质的空白，同单位；已校正数据 blank=0 并记录校正来源 |
| unit | 如 AU、µmol/L；吸光度不自动成为浓度 |

计算顺序：每孔 `value - blank` → 同实验/板/终点/组技术孔均值 → 除以同实验/板/终点的明确参考组均值 × 100 → 同实验跨板等权平均 → 跨独立实验等权均值和样本 SD（ddof=1）。参考组必须每板均存在且校正均值 >0。不跨板借用对照；跨板条件不一致时不能合并为同 group。负值保留并警示，不截断为零。

`normalized_percent` 仅是信号相对参考值百分比。活力终点通常参考合适的未处理/溶剂对照；炎症读数通常另选模型对照。不同对照的终点应拆成不同任务，不能用一个通用对照解释所有指标。脚本不直接输出“抑制率”“抗炎功效”或生存率阈值判断。

## 模拟消化

必需列：`experiment_id,sample_id,stage,replicate_id,readout,value,blank,unit,dilution_factor`。

`experiment_id` 是独立消化实验；`sample_id` 是跨实验可比较的配方/材料/条件标签（不是每次独立样品的新 ID）。`stage` 含阶段和时间点；不同分离级分须明确区分。`replicate_id` 是同实验/样品/阶段/指标下的技术测量 ID。相同 readout 必须同单位。`dilution_factor` >0。

逐行计算 `(value - blank) × dilution_factor`，先平均技术测量再跨 experiment_id 汇总。如果检测的是吸光度，此结果仍是吸光度；只有已通过合适标准曲线校准的浓度才能按浓度解释。脚本不拟合标准曲线、不计算水解度、质量回收率或生物可及性。后者还需适配方法、体积、级分、初始含量及质量基准；不能拿阶段浓度比直接代替。

## 输出与边界

JSON 包含输入绝对路径、SHA-256、UTC 运行时间、原始记录序号、孔位/技术重复、独立单位及分组汇总。记录序号是 CSV 逻辑记录位置（表头为 1），带换行的引用单元格不等同于物理文本行。

`n_biological` 仅在用户正确标记独立单位后成立。n=1 的 SD 为 null；脚本无法自动鉴别一个 ID 是否真正独立。同组样本数可以不等，应检查是否缺失；不自动构建配对检验。无 P 值、置信区间、假设检验、显著性星号或因果推断。全部计算是描述性的，正式统计另按研究设计实施。脚本不替代对实验设计、板布局、酶活、校准与细胞质量的审查。

## DOI

见 [verify_doi 工具说明](doi-verification.md)。元数据核对与论断的全文证据核验是两个步骤。默认离线；只有显式 `--online` 才向 Crossref 发送 DOI 请求，不上传实验 CSV、稿件或研究结果。
