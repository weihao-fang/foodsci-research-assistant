# FoodSci 具体能做什么

从你已有的材料开始。说明研究问题、想得到的成果，以及论文、记录、数据或初稿；总入口会按需使用相关模块。你可以从任何阶段进入，只完成本次需要的工作。

## 六个任务入口

0.7.0 使用一个总入口和五个任务入口：文献与综述、研究与实验设计、数据分析、写作与润色、审稿与投稿。文献检索/综述、研究规划/实验设计、写作/润色、专业审稿/投稿分别合并，内部细分参考继续保留。

`skills/foodsci-research-assistant/` 是包含完整参考、方法、脚本和样例的总文件夹。单独保留总入口也能使用内部模块；安装六入口套件时，五个任务入口共享同版本总文件夹资源，不能只取走任务入口。

## 1. 科研总入口：把请求变成本次可交付的任务

适合“我有几篇论文和一个想法，但不知道下一步先做什么”。FoodSci 区分你要找资料、设计研究、分析数据还是修改表达，核实当前文件、联网和计算能力，再完成本次范围内的工作。

**你提供：**研究问题、现有材料、目标交付、条件与范围。

**输入 → 交付：**“我研究发酵豌豆蛋白，有三篇论文和预实验表，请找到下一步最值得检验的问题” → 已有证据、关键不确定点、竞争解释和最小实验路线。缺少资料时说明受影响的部分，继续完成有依据的工作。

## 2. 文献与综述：从论文清单到问题和判断

可按真实检索条件筛选记录、去重、保留排除理由、核对 DOI/题名/年份，再定位全文中的方法、图表和支持范围。多篇资料按科学问题比较，处理模型、剂量、制备路径、相反结果及同研究多报告，形成提纲和正文。

**你提供：**主题、目的、检索范围、已有记录或全文。系统综述还需方案与实际检索筛选记录。无网络时可处理你给的文献集合，明确覆盖范围。

**输入 → 交付：**“比较发酵与酶解蛋白的消化后功能证据” → 检索/读取记录、报告—研究映射、证据表、矛盾来源、缺失的关键连接及请求范围内的综述正文。

仅有摘录就只依据摘录；元数据匹配不等于结论核验。缺少完整检索记录时不声称完成系统综述，不编造 PRISMA 计数或合并效应。[看历史合成演示](demos/literature-review.md)

## 3. 研究与实验设计：把机制故事拆成可区分的解释

拆解论文中的“主张—实验—对照—结果—支持范围”，判断每项实验在论证中的作用，再提出竞争解释和最小判别试验。采集前明确因素、水平、对照、独立单位、批次/随机化、取样时间、主要终点与分析计划。

**你提供：**目标主张、样品和模型、设备与资源、已完成实验、预实验变异或样本量依据。

**输入 → 交付：**“发酵改善可打印性，也伴随代谢物变化，怎样连接两者？” → 区分发酵、pH、组分和批次影响的对照；发酵运行、流变与打印批次的对应；必要终点、关键判别试验和分析计划。不默认所有项目都要做组学或动物实验。

十二项[方法入口](../skills/foodsci-research-assistant/references/methods.md)覆盖模拟消化、RAW264.7、抗氧化、多糖、蛋白、食品 3D 打印、发酵、斑马鱼、小鼠、功能评价、保鲜贮藏和生产放大。可依[模板与步骤](../skills/foodsci-research-assistant/references/ADD_METHOD.md)添加方法文档；新增文档不会自动产生专用计算程序。

## 4. 数据分析：先确认单位与比较，再报告数字

先核对数据字典、单位、独立样品、技术重复、配对、缺失和异常记录，再按设计选择方法、效应与不确定性。宿主具备软件和执行能力时，可为本任务编写并运行代码，保存结果、图表及复现记录；未运行时交付标明状态的方案或代码。

**你提供：**原始表、列含义、样本/批次/配对对应、处理和参考组、排除规则、实验记录及希望比较的问题。

**输入 → 交付：**“三次独立发酵，每批三个技术孔，比较配对处理” → 独立单位核对、清理记录、设计匹配的分析与结果；不会把每个孔都算独立 n。

固定脚本目前只做 RAW264.7 和模拟消化的有限描述性统计；DOI 工具可选联网核对 Crossref 元数据。其他方向依赖本任务代码与真实工具，不应理解为内置全领域统计或组学引擎。[看离线样例](demos/offline-analysis.md)

## 5. 写作与润色：交出正文，同时守住事实

从来源、方法和确认结果组织论文、章节、摘要与图注；处理生物食品术语、中英翻译、压缩和自然表达，删除空泛强调、重复澄清和假想反对意见。保留阴性结果、关联/推测程度、模型范围、数字、单位、n、CI、P 和引文含义。

**你提供：**原稿或结果表、研究问题、锁定事实、目标语言、篇幅和交付范围；有期刊要求时附来源。

**输入 → 交付：**“把这些结果写成英文 Results，再精修” → 可修改正文和必要事实问题；“只润色此段” → 直接交该段定稿，不额外启动检索或审稿。[看双语演示](demos/bilingual-polishing.md)

领域适配包括基质加工/蛋白多糖、材料与打印、发酵微生物、消化营养、细胞动物、RNA/通路、菌群多组学、预测/放大/保鲜。纯生物课题保留自身情境，不强加食品来源或用途。[纯生物输入](../examples/biology-results/input.md) → [历史 Results 输出](../examples/biology-results/output.md)

## 6. 审稿与投稿：让问题能够定位、修改和关闭

专业审稿核对贡献、创新依据、方法统计、领域适配和证据链。每项问题保留稿件位置、证据状态、影响与关闭标准。修订复审沿用原问题 ID，对照原稿、修稿与回复；承诺修改不能代替正文已经修改。

投稿审查核对目标期刊当前官方要求和材料，可起草 cover letter 或逐点回复。无法取得现行指南时，明确区分通用审查与未核验要求。

**输入 → 交付：**“这是原意见 Q1–Q5、修稿与回复，请复审” → 每个 ID 的关闭/部分解决/保留状态、真实定位及剩余修改；“准备投稿某期刊” → 已核对要求、材料缺项和可修改投稿文本。

这类交付是辅助性审查，不代表期刊决定、人类专家认证或未实际发生的多审稿人共识；发送邮件、提交稿件和公开发布按用户明确指示另行处理。

## 跨阶段保留同一条研究记录

沿用来源、主张、实验、样本和图表 ID：综述证据能追到原资料，分析样品能追到独立批次，正文数字能追到结果表，回复修改能追到修稿位置。带着已有成果进入下一阶段，无需重做已经完成的工作。
